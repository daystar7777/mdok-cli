# 실제 TUI 사용 흐름 점검

> 수정 전 감사 기록. 수정 후 결과는 [수정 및 재검증](fix-verification-2026-09-10.md) 참조.

## 방법과 집계

실제 `runTui`를 PTY에서 실행하고 키/SGR 마우스 입력과 SIGWINCH 크기 변경을
전달했다. 최종 화면 출력뿐 아니라 저장된 파일과 종료 시 세션을 검사했다.
설정·파일·Git 작업 위치는 매 실행 생성한 임시 디렉토리로 격리했다.
기존 View 너비 수정이 포함된 현재 소스를 빌드해 검사했다. 전역 npm 0.1.4
설치본이나 사용자의 실행 중인 터미널을 조작한 검증은 아니다.

26개 사용 흐름 전체 실행과 후속 표/셸 재검증을 종합하면 **16 통과 / 10 실패**다.
첫 표 테스트는 이미 정리된 입력이라 no-op을 통과시켰으므로, 실제 변경이
일어나는 입력으로 바꾸어 다시 실행했고 Undo 실패를 확인했다.
테스트 실행기의 종료 레이스도 제품 실패에서 제외했다.

기존 자동 테스트는 **48 + 5,130 = 5,178건 모두 통과**한다. 이 결과는
실제 이벤트 순서/포커스/상태 전이 검증을 대신하지 못한다.

## 원인 및 우선순위

### 우선 수정: 문서 손상/숨은 수정/Undo

- `focus` 순환이 `viewMode`에 관계없이 editor를 포함한다. View에서 Tab 후
  `X`를 입력·저장하면 `ALPHA…`가 `XALPHA…`로 변경된다.
- Backspace/Delete가 UTF-16 코드 단위 하나씩 제거한다. 저장 시 unpaired
  surrogate가 U+FFFD로 바뀐다. 표시 폭만 grapheme 단위로 바꾼 것으로는
  편집 안전성을 보장하지 못한다.
- 왼쪽 이동은 low surrogate에 도착한 뒤 `snapTrail`이 다시 오른쪽으로
  보정해 이모지 뒤에 머무른다.
- Undo 스택은 파일별이지만 타이핑 합치기용 `lastPush`는 공유된다.
  1.2초 이내 다른 탭에서 타이핑하면 첫 스냅샷이 누락된다.
- `applyFormat` / `applyTableFormat`이 Undo 스냅샷 없이 `setLines`를 호출한다.

### 이어서 수정: 비동기 저장·확인·패널

- `saveNow`는 저장 완료 시 현재 활성 탭에 `setBaseline(content)`를 호출한다.
  테스트에서 rename을 400ms 지연한 뒤 탭을 전환하자 B의 세션에 불필요한
  미저장 내용이 기록됐다. 콜백은 저장 대상 파일에 귀속되어야 한다.
- 별도 키 이벤트로 Ctrl+O를 누를 때 `quitArmed=false`로 초기화한다.
  두 번째 닫기 명령에 도달하기 전에 이전 확인 상태가 사라진다.
- 전역 Escape 분기가 셸 패널의 Escape 처리보다 먼저 반환한다.

## 재실행

```sh
npm run build
python3 scripts/audit-tui.py
python3 scripts/audit-tui.py 'emoji'
python3 scripts/audit-tui.py 'table formatting'
```

Python 3과 Node가 필요하다. 실패가 있으면 실행기는 종료 코드 1을 반환한다.
테스트 실행기와 fixture 외 제품 코드는 이번 점검에서 추가 수정하지 않았다.

## 미확인/후속 검증

전수 점검은 현재 주요 사용 흐름의 목록화/점검이지 모든 상태 조합의 증명은
아니다. IME 조합 입력, 전체 마우스 드래그/한글 파일명 클릭 좌표, OS별
클립보드, 실카메라 QR, 실제 LLM 네트워크와 Git 원격 동기화, 외부 파일 변경
중 탭 전환의 경쟁 조건은 후속 통합 검증이 필요하다.

코드상 외부 변경 watcher의 `dead` 플래그가 비동기 read 이후 검사되지 않고,
탭/헤더 클릭 좌표 일부가 표시 폭 대신 문자열 length를 사용하는 위험도 있다.
이 두 항목은 실제 재현 실패 건수에 포함하지 않았다.
