# mdok 전체 검토 — 2026-09-10

검토 대상: `main` / `2030819`와 현재 미커밋 변경(`README.md`, `src/i18n.ts`, `src/tui.tsx`, `desktop/`, `docs/`). 이번 작업은 검토와 설계이며 제품 코드 수정은 포함하지 않는다.

이전의 “본체는 꽤 완성됐다”는 평가는 기능 개수와 빌드 통과에 치우쳤다. 코드 검토 결과 데이터 복원·편집·비동기 상태 관리에 출시 전 수정이 필요한 결함이 있다. 기존 리뷰 결과를 전달하는 문서가 아니라 이번에 새로 수행한 검토다.

## 검증 범위

- 전체 소스 모듈, TUI의 입력·편집·탭·저장·LLM·렌더링, Electron 호스트, 배포 스크립트, 설계 문서 검토.
- `tsc --noEmit`: 통과.
- `tsx`로 현재 소스를 import하여 표 정리의 후속 문단 유실, Markdown hard break 제거, HTML script 보존을 재현.
- emoji 커서 이동·삭제 로직의 UTF-16 동작을 작은 입력으로 재현.
- 이전 빌드 검사에서 CLI 빌드/기본 명령 통과, desktop 의존성 부재로 desktop 빌드 실패. 이번에는 설치·패키징·실제 GUI 테스트를 수행하지 않음.
- 실제 LLM 요청, Git 변경 작업, 부하 시험, 외부 보안 감사는 수행하지 않음. 아래에서 실행 재현과 정적 코드 근거를 구분한다.

## 출시 전 수정할 항목

### R1 · P1 · 미저장 세션 복구 데이터가 다시 사라질 수 있음

근거: `src/index.ts:199`, `src/tui.tsx:277`, `src/tui.tsx:289`, `src/tui.tsx:558`.

세션의 미저장 `content`를 읽은 뒤 TUI는 같은 내용을 `baseline`으로 설정한다. 따라서 디스크와 달라도 clean으로 판단하고 다음 세션 저장에서 `content`를 생략한다. 복원 후 저장하지 않고 다시 종료·실행하면 복구 데이터가 사라질 수 있다. 파일을 인자로 지정한 경우에는 같은 경로의 세션 버퍼를 건너뛰기도 한다.

또한 미저장 버퍼를 `slice(0, 100000)`으로 자른다. 문서의 “100 KB 초과는 제외”와 다르게 UTF-16 100,000 code unit 이후를 조용히 유실한다.

수정 방향: 디스크 baseline, 복구 버퍼, 문서 ID를 분리하고 대용량 복구도 온전히 저장한다. 경로를 정규화하고 여러 프로세스의 세션 충돌도 분리해야 한다. 연속 두 번 재실행하는 회귀 테스트가 필요하다. 정적 코드 근거.

### R2 · P1 · 표 정리가 다음 문단을 덮어씀

근거: `src/lint.ts:175`.

구분선 없는 2행 pipe 표를 정리하면 구분선을 추가해 3행이 된다. `next[top + i] = ln`은 원래 영역을 확장하지 않고 다음 줄을 덮어쓴다.

재현 입력: `["| a | b |", "| c | d |", "KEEP THIS PARAGRAPH"]`.
실제 결과: `["| a | b |", "|:--|:--|", "| c | d |"]`.

수정 방향: 원래 표 영역만 `splice`로 치환하고 escaped pipe/코드 블록 경계를 파싱한다. 실행 재현 완료.

### R3 · P1 · 비동기 완료가 다른 탭의 상태를 변경

근거: `src/tui.tsx:541`, `src/tui.tsx:1313`.

A 저장 직후 B로 이동하면 A 저장 완료가 현재 탭의 `setBaseline(content)`를 호출한다. 파일 watcher도 await 이후 현재 탭 여부를 확인하지 않는다. cleanup에서 설정하는 `dead`가 읽히지 않아 이전 파일의 읽기 결과가 현재 버퍼를 대체할 수 있다.

수정 방향: 문서 ID별 상태와 작업 revision을 사용하고 완료 결과를 원래 문서에만 반영한다. 동일 파일 저장은 직렬화한다. 저장/읽기를 지연시킨 뒤 탭을 전환하는 테스트 필요. 정적 코드 근거, 실제 타이밍 테스트 미수행.

### R4 · P1 · AI rewrite가 선택 바깥 내용이나 다른 문서를 바꿀 수 있음

근거: `src/tui.tsx:817`, `src/tui.tsx:839`, `src/tui.tsx:852`.

문자 단위 선택의 시작·끝 column을 무시하고 해당 행 전체를 LLM에 전달하고 치환한다. 요청 결과에는 문서 ID와 원본 revision이 없다. 요청 중 탭 이동/편집 후 accept하면 현재 버퍼의 오래된 행 위치에 적용할 수 있다.

수정 방향: 정확한 선택 범위, 문서 ID, 원문 hash/revision을 보관한다. 적용 시 일치 확인 및 한 번의 undo 가능한 transaction을 수행한다. 협업에서는 상대 위치와 원문 재검증이 필요하다. 정적 코드 근거.

### R5 · P1 · 저장 시 관계없는 변경까지 자동 커밋

근거: `src/config.ts`의 `gitSync: true`, `src/tui.tsx:919`, `src/git.ts:97`.

기본 활성화된 자동 커밋이 저장소 루트에서 `git add -A`를 수행한다. 사용자가 열지 않은 소스, 삭제, 미추적 파일도 포함된다. 기존 staged 변경까지 커밋할 수 있다. 저장 파일이 다른 저장소에 있어도 `process.cwd()` 기반 저장소를 대상으로 한다.

수정 방향: 명시적인 opt-in, 파일별 저장소 탐지, 대상 파일 한정 staging/commit 및 기존 index 보존. 웹 협업 프로토콜과 Git을 분리한다. 정적 코드 근거, 실제 커밋은 실행하지 않음.

### R6 · P1 (웹 사용 시) · HTML 미리보기의 신뢰 경계 없음

근거: `src/html.ts:18`.

`markdownToHtml("<script>alert(1)</script>", "test")` 결과에 script가 그대로 남는 것을 확인했다. 현재는 HTML 내보내기이지만 이를 인증된 웹 앱의 미리보기로 재사용하면 XSS 경로가 된다. E2EE 키가 브라우저에 있으므로 특히 출시 차단 항목이다.

수정 방향: raw HTML 기본 차단 또는 허용 목록 기반 sanitization, URL scheme 검증, 강한 CSP, 미리보기 sandbox/별도 origin. 링크·이미지 외부 요청도 명시적으로 처리한다. [Marked도 sanitization을 제공하지 않는다고 명시한다](https://marked.js.org/).

### R7 · P2 · Undo/Redo가 모든 편집을 추적하지 않음

근거: `src/tui.tsx:329`, `src/tui.tsx:338`, `src/tui.tsx:1040` 이후 편집 action들.

타이핑 병합 시간이 전역이므로 A에서 입력 후 1.2초 내 B로 이동해 입력하면 B의 첫 undo snapshot이 생략된다. format, replace-all, AI accept에는 `pushUndo`가 없다. Vim normal 이동 문자도 입력으로 분류해 불필요한 undo snapshot을 만든다.

수정 방향: 문서별 transaction과 undo manager로 일원화. 협업에서는 자신의 변경만 되돌리는 undo 정책을 사용한다. 정적 코드 근거.

### R8 · P2 · Emoji 이동/삭제 및 포맷 시 Markdown 의미 손상

근거: `src/tui.tsx:2004` 이후, `src/tui.tsx:2040`, `src/lint.ts:44`.

`😀` 뒤에서 왼쪽으로 이동하면 low surrogate 위치를 다시 오른쪽으로 보정하여 이동하지 않는다. backspace/delete는 UTF-16 한 단위를 삭제해 깨진 surrogate를 남긴다. Vim 분기에도 단위 삭제가 있다. 작은 입력에서 동일 연산 재현 완료.

`formatMd`는 hard break인 줄 끝 공백 두 개를 삭제하고 코드 블록 내부 공백/빈 줄도 변경한다. `["line  ", "next"]`가 `["line", "next"]`로 바뀌는 것을 확인했다.

수정 방향: grapheme 단위 커서·삭제와 Markdown 문맥별 formatting. 조합형 한글, ZWJ emoji, variation selector, code fence를 테스트한다.

### R9 · P2 · Electron 파일 열기·종료 경로 미완성

근거: `desktop/src/renderer/renderer.js:67`, `desktop/src/main.ts:45`, `desktop/src/main.ts:65`, `desktop/package.json`.

Electron 35를 사용하면서 제거된 `File.path`에 의존한다. 파일을 다시 열 때 이전 PTY를 kill하며 이전 PTY의 onExit가 창을 닫을 수 있다. 창 닫기는 TUI의 미저장 확인/flush와 연동되지 않는다. `stage-bin` 스크립트 대상 파일도 없다.

수정 방향: native dialog 또는 preload의 webUtils, PTY 세대별 종료 처리, 저장/복구 flush 후 종료 handshake, 패키징 pipeline 검증. [Electron 공식 breaking changes](https://www.electronjs.org/docs/latest/breaking-changes)에 File.path 제거 근거가 있다. 정적 코드 근거, GUI 재현 미수행.

### R10 · P2 · 배포 검증 및 LLM timeout 누락

근거: `.github/workflows/release.yml:75`, `src/index.ts:40`, `src/llm.ts:65`.

GitHub Packages publish job은 새 checkout에서 install/build/artifact download 없이 `npm publish`를 실행한다. dist는 gitignore 대상이고 prepack도 없어 실행 파일 누락 위험이 있다. 패키지 버전은 0.1.1인데 CLI 버전은 0.1.0이다. CI는 태그 위주이며 PR 회귀 테스트가 없다.

TUI가 `ctl.signal`을 전달하면 `opts.signal ?? AbortSignal.timeout(...)`에서 timeout이 적용되지 않는다. 비스트리밍 요청도 명시적 timeout이 없다.

수정 방향: clean checkout에서 install/build/pack 후 tarball 설치 검증, PR CI, 버전 단일 원본, 취소 signal과 timeout 결합. 정적 코드 근거.

## 구조 및 운영 관찰

- TUI 약 2,573행에 편집·상태·I/O·LLM·Git·마우스가 함께 있다. 파일을 나누는 것보다 먼저 문서 상태와 transaction의 소유권을 정리해야 한다.
- 원자적 rename은 유용하지만 fsync 없는 구현은 전원 손실 내구성을 보장하지 않는다. 기존 파일 mode도 보존하지 않아 API key 설정은 umask에 따라 읽기 권한이 넓어질 수 있다. config는 0600, 복구 데이터는 전용 보호 디렉터리 권장.
- 문서의 “CJK-correct”, “dirty baseline 복원”, “tested”, “120초 timeout” 등은 구현/검증 수준과 불일치한다. 웹 출시 기준은 문서 체크박스가 아니라 회귀 테스트와 복구 시험이어야 한다.
- HTTP 서버, 인증, 사용자별 접근 권한, DB, 웹 UI, 협업 transport는 아직 없다. 기존 쉘 실행은 로컬 기능으로 유지하고 웹 서버 권한으로 사용자 명령을 실행하지 않는다.
- `mdok.net`은 이번 환경의 DNS 조회에서 해석되지 않았다. 도메인 미등록이라고 단정할 수는 없으며 배포 전 DNS 소유권·레코드 검증이 필요하다.
