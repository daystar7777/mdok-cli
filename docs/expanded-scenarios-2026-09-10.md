# 확장 시나리오 검증

## 범위

수천 개의 생성 입력을 더 늘리는 대신 저장·Git·LLM·세션·Markdown·HTML·
입력 처리에 22개의 명시적인 시나리오를 추가했다.
실제 Git 저장소와 파일 쓰기는 생성한 임시 디렉토리에서만 실행했다.
세션 저장 경로는 테스트 모듈에서만 교체했고 사용자 설정은 읽지 않았다.
LLM fetch는 mock이며 외부 API 호출이나 추가 외부 모델 검토는 하지 않았다.

## 결과

- 새 시나리오: 22건, 15 통과 / 7 실패. 단독 실행과 전체 실행에서 동일.
- 대량 검증 전체: 5,130건, 5,120 통과 / 10 실패, 약 7.80초.
- 별도 기존 회귀 테스트: 38건 통과.
- TypeScript 빌드와 `git diff --check`: 통과.
- 제품 코드 수정/커밋/푸시/배포 없음.

## 새로운 실패 (6개 문제, 7개 테스트)

| 문제 | 재현 | 영향 |
| --- | --- | --- |
| SSE 종료 신호 무시 | answer → DONE → unexpected | answerunexpected를 반환 |
| 토큰 콜백 예외 누락 | onToken에서 예외 발생 | JSON 파싱 오류처럼 삼키고 성공 반환 |
| 심볼릭 링크 교체 | 동기/비동기 저장 각각 테스트 | 링크는 일반 파일로 바뀌며 원래 대상은 이전 내용 유지 |
| Git 한글 경로 해석 | core.quotePath=true, 한글.md 추가 | 실제 파일명으로 상태 조회 실패 |
| 세션 활성 탭 이동 | files=[null,a,b], active=1 | 손상 항목 제거 후 a 대신 b가 활성화 |
| 코드펜스 종류 혼동 | backtick 열기 뒤 tilde | 열린 코드블록을 닫힌 것으로 판정 |

심볼릭 링크 검증의 요구 조건은 “링크/원본에 의도대로 저장하거나 명시적으로
거부하고 기존 링크를 보존”이다. 제품이 링크 교체를 의도한다면 정책·사용자
경고를 먼저 명시해야 한다. 현재는 성공으로 처리하면서 원본은 갱신하지 않는다.

## 통과한 새 시나리오

- LLM 부분 수신 후 연결 오류 전파, 요청 전 취소 전파, keepalive/usage 처리,
  요청 문서·system 메시지 보존 및 endpoint 슬래시 처리
- 디렉토리에 잘못 저장 시 내부 문서 보존과 임시 파일 정리
- Git 삭제 커밋의 staged 격리, 다른 파일의 staged rename 보존,
  커밋 실패 시 기존 staged 내용 보존, 저장소 밖 동작, upstream 없음 판별
- 세션 동시 저장의 완전한 snapshot 보존, 잘린 UTF-8 JSON의 안전한 실패
- 인용문 코드블록 사례 보존, HTML title의 태그 주입 방지,
  bracketed paste/focus 이벤트에서 QR 명령 미실행

## 기존 실패 3건

이번 전체 실패 10건 중 3건이며 새로 발생한 회귀가 아니다.

## 재실행 및 한계

```sh
node --import tsx --test tests/scenarios.test.ts
npm run test:mass
npm test
```

테스트 코드는 `tests/scenarios.test.ts`에 있다. 실제 카메라/폰트/터미널의
픽셀 검증, 디스크 고갈·전원 차단·fsync, 실제 원격 Git 및 네트워크 장애는
이번 실행에 포함되지 않았다. 통과 건수는 전체 제품의 안전성을 보장하지 않는다.
