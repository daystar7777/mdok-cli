# mdok 제품 개발 기준

2026-09-10 사용자 요구사항을 반영한 개발 순서와 제품 품질 기준. 구현 완료 목록이 아니다. 개발 순서와 기능 범위는 이 문서를 기존 roadmap/web-service-design의 이전 제안보다 우선한다.

## 개발 순서

1. 데스크톱 버전: 비로그인 로컬 편집.
2. 앱 버전: Android/iPhone, 기타 플랫폼은 착수 시 구체화.
3. 웹 페이지: 첫 개발 목표의 종료 지점. 소개/다운로드와 비로그인 웹 편집기를 포함하는 작업 가정이며 웹 편집기의 정확한 범위는 화면 설계 때 확정.
4. 계정 기반 사용자당 5MB 할당, E2EE 클라우드 저장과 동기화.
5. 사용자 초대 가입.
6. 유료화.

문서별 특정 사용자 열람 권한은 확정된 후속 요구사항으로 계정/클라우드 단계의 설계·개발 범위에 포함한다. 가입 초대와 문서 접근 권한 부여는 별개 기능이다. 실시간 협업도 장기 요구사항으로 유지하되 첫 목표의 출시 조건으로 넣지 않고 세부 구현 시점은 사용자가 정한다.

## 데스크톱부터 적용할 GUI 기준

GUI의 편의성·친숙함·신뢰감은 핵심 제품 요구사항이다. 기존 Electron+xterm 스케치는 최종 사용자 GUI로 확정된 것이 아니다. 문서 중심의 그래픽 편집기를 목표로 하며 기존 CLI/TUI의 재사용 범위는 문서 처리와 adapter 중심으로 판단한다.

- 일관된 문서 목록, 편집 영역, 필요한 때 여는 미리보기/AI 패널. 모바일은 좁은 화면에서 단계별로 전환한다.
- 플랫폼에 맞는 파일 열기/저장/검색/Undo 단축키, 메뉴, 키보드 탐색, focus, screen reader 이름.
- 본문 가독성, 적절한 줄 길이/행간, 글꼴 fallback, 밝은/어두운 테마, 충분한 대비와 터치 영역.
- 저장 중/기기에 저장됨/저장 실패/미저장 복구를 실제 상태에 맞게 표시한다. 미래에는 로컬 저장과 클라우드 동기화 완료를 구분한다.
- AI 결과와 원문을 비교하고 새 문서로 저장/명시적 적용/취소할 수 있어야 한다. 원문을 자동 덮어쓰지 않는다.
- 초기 화면에 미구현 계정/공유/결제 버튼을 과도하게 노출하지 않는다.
- 화면 시안 → 클릭 가능한 주요 흐름 → 실제 입력/파일 저장 시험 순으로 검증한다. 파일 열기→수정→저장→재실행 복구를 대표 사용 흐름으로 삼는다.

## 다국어와 AI 번역의 분리

UI 다국어는 네트워크나 LLM 없이 동작하는 정적 locale catalog로 제공한다. 메뉴, 설정, 오류, 접근성 문구, 날짜/숫자, 복수형까지 포함한다. 한국어/영어를 우선 검증하고 기존 README의 일본어/중국어를 확장 후보로 둔다. 최종 지원 언어 목록은 아직 미정이다.

언어별 길이 차이와 CJK 입력/조합, emoji, 줄바꿈을 디자인 단계부터 검사한다. 언어를 국기로 표시하지 않는다. OS 언어 기본값과 사용자의 명시적 변경을 지원한다. 지원 언어에 RTL이 포함되면 레이아웃 미러링과 bidi를 함께 테스트한다.

LLM 문서 기능은 번역, 선택/전체 요약, 문장 다듬기를 포함한다. 원문 언어, 목표 언어, 요약 길이를 UI 언어와 별도로 설정한다. 코드 블록·링크 목적지·front matter·표 구조를 보호하고 긴 문서는 문서 구조에 따라 나눈다. 번역 용어 일관성과 요약 사실 보존은 언어별 표본 문서로 평가한다.

## 문서별 열람 권한과 E2EE

후속 클라우드 기능: 문서 소유자가 특정 계정에 열람 권한을 주고 목록 확인·철회한다. 문서 ID, 소유자, permission API와 저장 adapter를 초기 설계에 준비하되 비로그인 제품에서 가짜 공유 기능을 만들지 않는다.

기존 web-service-design의 workspace 공통 대칭키를 개별 문서 reader에게 전달하면 다른 문서도 해독할 수 있다. 따라서 문서별 랜덤 키/epoch와 recipient별 key envelope를 사용한다. workspace 관리는 문서 복호화 권한과 분리하고 문서 키를 workspace 키에서 수신자가 역산 가능한 방식으로 만들지 않는다. 제목/경로를 포함하는 metadata도 권한 범위와 같은 경계로 분리한다.

서버 ACL과 클라이언트 키 배포를 함께 검사한다. reader는 복호화할 수 있지만 writer 기기 서명이 없으면 문서 변경을 승인하지 않는다. 철회는 서버 접근 차단과 문서 epoch/key rotation을 함께 수행한다. 이미 상대가 읽고 보관한 내용까지 회수할 수 있다는 약속은 하지 않는다.

실시간 협업 transport는 기존 기술 설계의 참고 대상으로 유지하되 문서별 key/permission schema로 재검토한다.

## 무료 LLM API 검토

조사일: 2026-09-10. 무료 한도와 모델 목록은 변동되며 실제 호출/언어별 품질 평가는 아직 하지 않았다.

| 후보 | 확인한 조건 | mdok 적용 판단 |
|---|---|---|
| GroqCloud | 무료 플랜에 모델별 요청/토큰 제한. 기본 inference 본문은 보관하지 않으나 장애/악용 조사 등 예외가 있고 ZDR 설정 제공 | 첫 연동 시험 후보. 모델별 번역 품질은 별도 검증 |
| Gemini Developer API | 일부 모델 무료 tier. 비결제 서비스에는 입력/출력 제품 개선 사용 및 사람 검토 조건, 민감정보 전송 금지 안내 | 공개 샘플 평가 후보. 비공개 문서 기본 무료 backend로는 부적합. 지역/청소년 접근 관련 조건도 배포 범위와 대조 필요 |
| OpenRouter 무료 모델 | 무료 모델/라우터 제공, 낮은 rate limit, 공급자별 정책 상이 | 모델 비교/선택 후보. 제품 기능은 자동 랜덤 라우팅보다 모델과 공급자 정책을 명확하게 표시 |

근거: [Groq limits](https://console.groq.com/docs/rate-limits), [Groq data controls](https://console.groq.com/docs/your-data), [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing), [Gemini terms](https://ai.google.dev/gemini-api/terms), [OpenRouter FAQ](https://openrouter.ai/docs/faq).

첫 비로그인 데스크톱은 사용자 API key로 무료 tier 또는 유료 API에 직접 연결하는 BYOK를 제안한다. mdok 계정 없이도 가능하지만 공급자 계정/key는 필요하다. 서비스 공용 API key를 배포 앱에 넣지 않는다. 이후 mdok 제공 무료 체험을 원하면 서버 proxy, 남용 방지, 사용량/비용 제한과 별도 데이터 처리 고지가 필요하다.

사용자에게 무료라는 것과 운영자의 원가가 0이라는 것은 다르다. 무료 API만으로 전체 제품의 지속적인 무제한 사용을 보장하지 않는다. quota 소진은 명확히 알리고 유료 전환이나 다른 공급자 전송을 자동으로 수행하지 않는다.

E2EE 저장 중인 문서도 외부 AI를 실행하면 선택한 평문이 AI 공급자에게 전달된다. 실행 UI에 대상 내용·제공자·목적을 표시한다. 서버 proxy를 사용할 경우 mdok 서버도 요청 평문을 볼 수 있다는 점을 구분한다. 번역/요약이 동작하지 않아도 편집·저장 기능은 정상 동작해야 한다.
