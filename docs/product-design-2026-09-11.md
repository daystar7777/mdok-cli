# mdok 통합 제품 명세·설계 v0.1

후속 상세 설계: [LaTeX 진단·구분자 변환·Markdown 구조 diff](math-and-structural-diff-design.md). 현재 구현과 별개인 확장 제안이다.

작성: 2026-09-11. 상태: 설계 제안, 구현 완료 명세가 아님.

사용자가 정한 개발 순서를 유지하면서 대화에 흩어진 리더 UX, 다국어, AI/TTS, QR, E2EE 요구를 통합한다. 기존 문서와 충돌할 때 이 문서의 최신 요구사항 정리를 우선한다. 아래 ‘제안’은 아직 사용자 확정이 아니다.

## 1. 제품 방향과 현재 상태

**로그인 없이 Markdown을 편하게 읽고 편집하며, 필요할 때 기기·사람·AI와 연결하는 문서 리더/편집기.** 파일의 이식성, 가독성, 저장 신뢰성이 기능 수보다 우선한다.

현재 확인된 구현:

- CLI/TUI npm 0.1.5: 로컬 편집, 미리보기, Undo, 검색/포맷, 한국어·영어, BYOK 질문/재작성, Git 기능, QR 송신.
- `desktop/`은 Electron+xterm TUI 호스트 골격이다. 리더형 GUI가 완성된 상태가 아니다.
- QR 이미지/카메라 수신 UI, 독립 GUI, 모바일 제품, 웹 편집기, 계정·클라우드·E2EE 협업·TTS는 미구현.
- QR 디코딩 테스트가 있다는 사실과 사용자가 쓸 수 있는 수신 기능은 구분한다.

## 3. 단계별 범위와 종료 조건

| 단계 | 제품 범위 | 종료 조건 |
| --- | --- | --- |
| D1 데스크톱 | 비로그인 파일 열기/읽기/소스 편집/저장/복구, 리더 설정, 다국어, QR 송수신, 기본 AI/TTS | 실제 OS에서 파일 열기→편집→저장→재실행 복구 검증 |
| D2 앱 | Android/iPhone 읽기+편집, 파일 가져오기/내보내기, 카메라 QR, 로컬 TTS, 설정 | 기기별 IME·권한·중단 복구·공유 시트·가상 키보드 검증 |
| D3 웹 | mdok.net 소개/다운로드/도움말, 비로그인 웹 편집기, 로컬 복구·가져오기/내보내기 | 네트워크/브라우저 기능 부족 시에도 문서 회수 가능. **첫 목표 종료** |
| D4 계정·5MB | 계정/기기/복구, 문서별 E2EE 저장, 동기화, 특정 사용자 읽기 공유 | 서버에 본문/키 평문 없음, 복구·철회·quota 검증 |
| D5 초대 가입 | 신규 가입 초대 발급·만료·회수·한도·남용 방지 | 기존 문서 공유 초대와 구분, 재사용/경쟁 요청 검증 |
| D6 유료화 | 상품·용량·결제·갱신·해지·유예·내보내기 | 결제 실패/중복 이벤트가 데이터 손실을 일으키지 않음 |

D4는 내부 계정으로 먼저 검증하고 D5에서 초대 가입을 연다. D4가 불특정 공개 가입을 뜻하지 않는다. 실시간 공동 편집은 D4의 기반 위에 별도 게이트 C1로 설계하며 D5 전/후 어느 시점에 출시할지는 사용자가 정한다. 이 문서가 개발 순서를 임의로 추가 확정하지 않는다.

첫 목표에서 제외: 로그인 요구, 서버 문서 보관, 클라우드 동기화, 권한 공유, 실시간 협업, 초대 가입, 결제. 다만 이를 위한 문서 ID·저장 adapter·권한 인터페이스는 준비한다. 비로그인 사용자에게 동작하지 않는 공유 버튼을 보여주지 않는다.

‘기타 앱 플랫폼’은 아직 미정. 데스크톱 대상은 macOS/Windows/Linux를 제안하며 실제 배포 지원 표는 패키징 시험 뒤 확정한다. 앱은 읽기 전용으로 축소하지 않는다.

## 4. GUI 정보 구조와 조작

데스크톱: 상단 문서명/실제 저장 상태/읽기·편집 전환, 선택적 왼쪽 최근 문서·목차, 가운데 본문, 필요한 때만 오른쪽 AI/설정. 하단 읽기 진행과 TTS 제어. 한 파일을 열면 그 파일만 표시하는 기본 동작을 유지한다. 이전 작업 복원과 추가 문서 열기는 명시적인 별도 동작이다. 추가 탭이 생겨도 모든 문서를 강제로 분할하지 않는다.

모바일: 읽기 본문이 기본, 목차와 설정은 시트, 소스 편집은 별도 화면. 휴대폰에 데스크톱 두 패널을 축소해 넣지 않는다. 넓은 태블릿에서만 분할을 허용한다.

### 읽기/편집 상태 전환 제안

| 현재 상태 | 동작 | 결과 |
| --- | --- | --- |
| 읽기 | 편집 버튼/단축키 | 소스+뷰어. 모바일은 소스 화면 |
| 읽기 | 본문 더블클릭 | 해당 블록 소스 위치로 편집 진입하는 **선택 옵션** |
| 분할 편집 | 뷰어 한 번 클릭 | 뷰어 포커스/텍스트 선택. 패널은 닫히지 않음 |
| 분할 편집 | 읽기 버튼 | 소스를 접고 읽기 위치 유지 |
| 분할 편집 | 뷰어 더블클릭 | 읽기로 복귀하는 선택 옵션. 선택·링크와 충돌 시험 후 확정 |
| 모든 상태 | 문서 변경·창 닫기 | 미저장 확인 또는 검증된 복구 저장. 조용히 폐기하지 않음 |

일반적인 더블클릭 단어 선택, 링크 열기, 코드 복사와 모드 전환은 충돌할 수 있다. 따라서 버튼을 항상 제공하고 더블클릭을 유일한 진입 경로로 만들지 않는다. 모바일 더블탭 확대/선택을 가로채지 않는다. 전환 시 저장을 강요하지 않고 현재 버퍼를 읽기에도 반영한다.

소스-뷰어 위치 연결은 Markdown 블록의 source range로 매핑한다. 전체 스크롤 비율만으로 대응하지 않는다. 편집 후 블록이 사라지면 인접 블록으로 이동하며 읽기 위치를 잃지 않는다.

### 리더 설정

- 테마: 시스템 기본 + 라이트/다크/고대비. 앱 테마와 문서 표현 테마를 구분하되 첫 UI에서는 하나의 간단한 선택기로 제공.
- 폰트: 본문/코드 구분, OS fallback, 크기·행간·본문 폭. 임의 웹폰트 다운로드는 자동 실행하지 않음.
- 줄바꿈: 본문 reflow, 코드/표는 가로 스크롤 기본 및 줄바꿈 옵션. 표현 변경으로 원본 Markdown을 수정하지 않음.
- 읽기 방식: 연속 스크롤 기본, 단일 페이지 넘김 옵션, 충분히 넓을 때 두 페이지 옵션.
- 두 페이지는 별도 문서 두 개가 아니라 같은 문서의 연속 페이지. 코드/표를 무리하게 분할하지 않고 좁아지면 한 페이지로 전환.
- 확대/축소: 문서 배율과 글꼴 크기를 혼동하지 않게 표시. 초기 제안 50–200%, 100% 복원. OS/브라우저 접근성 확대를 제한하지 않음.
- 페이지 번호는 폰트·폭·배율에 따라 바뀌는 임시 표시. 책갈피/읽던 위치는 source anchor로 저장.
- 읽기 설정은 기기별 기본, 문서별 읽던 위치는 로컬에 저장. 이후 설정 동기화는 별도 동의 항목.
- 로딩/빈 파일/깨진 문서/권한 거절/저장 실패 화면을 정상 화면과 함께 설계.

## 5. 플랫폼과 코드 구조

**제안: React+TypeScript 공통 GUI, CodeMirror 기반 소스 편집, OS 기능은 adapter로 분리.** 직접 만든 TUI 키 입력 엔진을 GUI에 이식하지 않는다. 기존 Electron 호스트는 유지하되 새 GUI의 최종 UX로 간주하지 않는다.

데스크톱 셸은 Tauri를 우선 검증 후보로 두고 기존 Electron을 대안으로 비교한다. Tauri는 Android/iOS 개발 경로도 문서화하지만 이것만으로 모바일 입력·플러그인 품질을 보장하지 않는다. 앱 선택은 한글 IME, 파일 권한, TTS, QR 카메라 실기기 spike 결과로 결정한다. 현재 작업은 셸 교체나 새 dependency 설치를 수행하지 않는다.

```text
기존 src/ CLI·TUI         새 desktop / mobile / web GUI
          │                       │
          └──── 문서·Markdown·전송 공통 서비스 ────┘
                              │
       파일 / 브라우저 저장 / 키 저장 / TTS / AI / QR adapter
                              │
                  후속 E2EE 동기화 client
                              │
            계정 API + 암호문 저장·중계 서버
```

점진적으로 `packages/core`, `packages/reader-ui`, `packages/platform`, `packages/transfer`를 추출한다. 후속 `packages/sync`, `packages/crypto`는 별도 모듈이다. npm CLI 경로를 깨는 대규모 monorepo 이동을 첫 작업으로 하지 않는다. Node 파일 I/O·shell·Git를 브라우저 bundle에 넣지 않는다. React 상태 한 곳에 저장·키·네트워크를 모두 몰아넣지 않는다.

핵심 인터페이스 초안:

| 경계 | 책임 |
| --- | --- |
| DocumentSession | 안정적인 docId, revision, buffer, dirty 상태, transaction, Undo, view anchor |
| DocumentStore | open/read/write(expectedRevision)/recover/export; 로컬 경로·모바일 URI·브라우저 handle 차이 은닉 |
| ReaderPreferences | 테마·폰트·폭·배율·페이지 모드, versioned 설정 migration |
| SecretStore | OS 보호 저장소 또는 세션 전용 키. 일반 UI 설정과 분리 |
| AiProvider | 모델 목록/기능, 스트리밍·취소·오류, 요청 범위/정책 표시 |
| SpeechProvider | 음성 목록·언어·local/remote/unknown, 재생·중지·속도·현재 블록 |
| TransferCodec | 버전·조각 합치기·중복/손상 검증·제한된 복원. 카메라/화면과 독립 |
| SyncClient (후속) | 암호문 outbox/ACK/재접속/권한·epoch 검증 |

CodeMirror의 로컬 Undo와 후속 CRDT Undo를 두 겹으로 동시에 적용하지 않는다. 공동 편집 도입 시 로컬 사용자의 transaction만 취소하는 정책과 편집기 binding을 따로 검증한다.

## 6. 저장과 데이터 보존

로컬 독립 모드에서 `.md` 파일이 원본이다. 앱 내부 복구본은 원본과 구분한다. 협업 모드에서는 암호화 CRDT 상태가 권위 있는 공동 상태이고 `.md`는 내보내기/로컬 사본이다. 같은 파일에 Git 동기화와 CRDT를 경쟁 writer로 붙이지 않는다.

- 파일명 변경에도 docId 유지. 외부에서 가져온 새 파일/사본의 ID 충돌은 새 ID 발급으로 처리.
- 파일 저장은 파일별 직렬화와 revision 비교. 외부 변경+로컬 수정은 비교/사본 저장 선택을 제공하고 덮어쓰지 않음.
- 자동 복구 저장과 사용자의 원본 저장을 분리. 자동 복구 주기·최대 용량은 측정 후 결정하고 큰 문서를 조용히 제외하지 않음.
- 저장 상태: ‘수정됨 → 복구본 기록 중 → 이 기기에 복구됨 / 파일 저장 중 → 파일 저장됨 / 실패’. 후속 ‘클라우드 대기/동기화 완료’는 별도 상태.
- 브라우저 내부 저장은 원본 파일에 저장됐다는 뜻이 아님. 사이트 데이터 삭제/시크릿 모드 위험을 알리고 내보내기 제공.
- 경로 handle 사용이 불가능하면 파일 업로드+다운로드로 기능 저하. 웹 첫 실행이 오프라인이면 설치되지 않은 앱을 이용할 수 있다는 약속을 하지 않음.
- 평문 로컬 파일은 E2EE 보호 대상이 아니다. 후속 cloud vault 캐시/키는 암호화하고 로그아웃과 vault 잠금을 구분.
- Markdown/HTML은 불신 입력: sanitize, URL scheme 제한, 문서 내 script 실행 금지, 기본 외부 리소스 자동 로드 차단. 문서에서 shell 호출 불가.

## 7. 다국어와 접근성

UI 번역은 오프라인 정적 catalog로 제공한다. LLM 문서 번역과 분리한다. 한국어/영어를 첫 필수 언어로 제안하며 일본어/중국어 등 추가 언어는 검수 가능 범위에 맞춰 확정한다. README 번역을 UI 지원이라고 표시하지 않는다.

OS 언어 → 지원 locale 매칭 → fallback을 기본으로 하되 사용자 설정을 우선한다. 메뉴·오류·저장 상태·접근성 이름·날짜/숫자/복수형까지 catalog화한다. 일본어/중국어/RTL 문서 보존은 UI 언어 지원 여부와 무관하게 시험한다.

키보드 탐색, 읽기 순서, 명확한 focus, 스크린리더 이름, 색상 외 상태 표시를 기본으로 한다. IME 조합 중 저장/Undo/모드 전환, NFD 한글, 결합문자, emoji, 긴 번역과 200% 확대를 실제 화면에서 검사한다. 텍스트 폭 단위와 UTF-16 offset을 섞지 않는다.

## 8. AI와 TTS

AI 1차 범위 제안: 선택/전체 번역, 선택/전체 요약, 문장 다듬기. 결과는 별도 패널에서 비교→복사/새 문서/명시적 적용. 생성 중 원문 revision이 바뀌면 기존 위치에 자동 적용하지 않는다. 번역 목표 언어와 UI 언어를 별도 관리한다.

공급자 catalog 후보: OpenAI, Anthropic, Gemini, OpenAI 호환 endpoint, Groq/OpenRouter 및 로컬 endpoint. 이 목록은 모두 구현됐다는 뜻이 아니다. 실제 모델·무료 한도·약관은 adapter 구현 시 공식 문서로 재검증하며 무료/유료 API와 채팅 서비스 구독을 혼동하지 않는다.

- 비로그인 제품도 BYOK 사용 가능. 앱에 서비스 공용 key를 넣지 않음.
- 전송 전 제공자·모델·선택 범위·원격 처리 여부 표시. 다른 열린 문서를 기본 자동 포함하지 않음. 현재 TUI 다중 탭 컨텍스트는 새 정책 적용 대상.
- 무료 옵션은 경고만 붙이면 끝이 아님: 민감정보 전송 방지 UX, 이용 가능 지역/조건 확인, quota·오류 처리 필요. 실패 시 다른 업체/유료 모델로 자동 전환하지 않음.
- 웹 직접 호출은 CORS/키 노출 조건을 adapter별 검증. 불가능하면 비활성화하거나 별도 동의 relay. relay가 평문을 보면 그 사실을 밝힘.
- 외부 AI 호출은 저장 E2EE와 별개의 평문 반출이다. 외부 TTS도 동일.
- 모델 출력은 불신 입력이며 자동 실행하지 않음. 긴 문서 분할 시 코드·링크·front matter 보호, 용어/요약 사실 보존 평가.

TTS는 **OS/기기 로컬 음성 우선**, 없을 때 음성 설치 안내 또는 명시적 외부 제공자 선택. iPhone만 로컬, 다른 OS는 반드시 서버라는 구조로 만들지 않는다. 무료 여부와 오프라인 동작 여부는 별개다. 음성마다 local/remote/unknown 표시, 원격 음성에 문서를 자동 전송하지 않는다.

기본 UX: 재생/일시정지/중지, 속도/음성 선택, 현재 문단 강조, 문단 이동, 코드/URL 읽기 제외 옵션. 문서 변경 시 중지하거나 새 위치에서 재시작하고 이전 문서가 계속 읽히지 않게 한다. 모바일 백그라운드·잠금화면 재생은 별도 실기기 검증 전 지원을 약속하지 않는다.

## 9. QR·문자 전송

현재 MDOK1 프로토콜을 유지한다. 각 QR에 transfer ID·1부터 시작하는 index·count가 있으며 UI에 `1/17`, 수신은 `12/17 수집됨`과 빠진 조각을 표시한다. 송신은 현재 버퍼를 고정한 snapshot이며 자동 재생/수동 넘김/배율·가용 화면을 제공한다.

수신 입력: 모바일 카메라, 데스크톱/웹 이미지 파일·이미지 붙여넣기. 화면 캡처는 사용자 선택 이미지 또는 승인된 캡처 경로만 사용하고 항상 화면을 감시하지 않는다. 원격 TUI 화면을 로컬 PC에서 캡처해 복원할 수 있어야 한다. TUI 자체는 이미지 경로 입력을 통한 수신을 후속 제공하며 터미널 내부 카메라 접근을 전제하지 않는다.

수신 과정: 조각 수집 → 역순/중복 처리 → 모든 조각 완성 → hash 검증 → Base64·제한된 gzip 해제 → schema 검사 → 미리보기 → 열기/명시적 저장. 잘못된 같은 인덱스 조각은 충돌로 처리한다. 수신 name은 안전한 basename으로 제한하고 상대/절대 경로 탈출·덮어쓰기·자동 실행을 막는다.

기존 송신의 1MiB 본문/4096조각 제한과 호환하되 수신 측은 압축 크기·해제 크기·메모리·조각 수·시간 제한을 각각 둔다. 정확한 수신 envelope 상한은 파일명/JSON 오버헤드를 포함해 codec 구현 때 확정한다. 조각 손실·복수 전송 혼합·압축폭탄을 시험한다.

MDOK1은 암호화가 아니며 hash도 발신자 인증이 아니다. 캡처한 사람은 읽을 수 있다고 표시한다. 암호화 전송을 추가하면 별도 version과 키 전달 UX가 필요하고 기존 QR을 E2EE라고 부르지 않는다. 압축 문자 스트림은 같은 codec을 재사용하되 QR 수신 완성 이후 추가한다.

## 10. 후속 클라우드·공유·협업

docId별 무작위 문서 키와 epoch, 수신 기기별 key envelope를 사용한다. workspace 공통키를 reader에게 넘겨 다른 문서까지 열리는 설계는 폐기한다. 본문뿐 아니라 제목·경로·presence도 암호화 경계에 포함한다.

계정 인증과 복호화 권한은 별개. 기기 승인/공개키 검증/복구키/분실 기기 철회를 설계하고 서버가 바꾼 공개키를 무조건 신뢰하지 않는다. 권한은 owner/reader/writer로 구분하며 reader가 문서 키를 알아도 writer 서명 없이 변경을 승인하지 않는다. 최초 공유의 상대 키 신뢰 방식과 신규 사용자 이력 공개 범위는 보안 설계 게이트에서 확정한다.

권한 철회: ACL 차단+연결 종료+epoch/key rotation. 이미 읽어 보관한 사본은 회수 불가. 기존 기기와 복구 수단을 모두 잃으면 비밀번호 재설정만으로 평문을 되찾을 수 없음을 알린다. 암호 알고리즘을 자체 제작하지 않으며 구현 전 versioned 프로토콜·독립 보안 검토가 필요하다.

협업 후보는 Yjs binding+암호문 relay. 서버는 평문 CRDT를 병합하지 않는다. client transaction → 암호화 로컬 outbox → 서버 durable commit → ACK → 상대 서명/권한 검증→복호화 적용. 서버는 본문 의미를 검사할 수 없으므로 클라이언트에서도 크기/구조/권한 방어가 필요하다. 재시도·역순·중복·오프라인 epoch 변경은 복구 가능한 상태로 다룬다.

compaction은 승인 기기의 암호화 checkpoint와 tail을 함께 검증한 뒤 수행한다. 서버는 사용자/기기 ID·권한·크기·접속 시각 같은 metadata는 볼 수 있다. 웹 배포 코드가 악성으로 바뀌면 메모리의 키/본문을 훔칠 수 있다는 E2EE 한계도 명시한다.

5MB의 계산 단위는 미확정이다. 제안: 5,000,000 bytes의 현재 암호문 객체+metadata를 owner에게 귀속하고, 이력/로그는 별도 상한과 보존 정책을 둔다. 서버는 본문이 평문 기준 정확히 5MB인지 검증할 수 없으므로 평문 용량 과금은 채택 전 별도 설계가 필요하다. 공유 받은 사본은 원본 quota를 중복 차감하지 않는다. 초과 시 로컬 편집/내보내기는 유지하고 클라우드 새 저장을 중단하며 기존 내용을 삭제하지 않는다.

## 11. 서버·배포 구상

mdok.net은 소개/다운로드/문서, app.mdok.net은 웹 앱으로 분리하는 제안이다. D3는 정적 호스팅과 로컬 편집만으로 가능하며 계정 DB나 큰 서버가 출시 전제는 아니다. Contabo 후보는 D4 전에 상품 링크/지역/최종 요금/디스크/백업 조건을 재확인한다. 이 문서에서는 최신 가격·성능을 검증한 것으로 취급하지 않는다.

D4 초기 제안: TLS reverse proxy + API/암호문 relay + PostgreSQL + 별도 장애영역 백업. 사용자가 제시한 RAM/CPU만으로 동시 사용자 수를 보장하지 않는다. 서버에 범용 LLM inference를 함께 운영하는 계획은 기본 제외한다. 단일 VPS는 단일 장애점이며 백업 복원/권한/재접속 부하 검증 후에만 제한된 베타를 연다.

## 12. 구현 순서와 검증 게이트

다음 구현 묶음 제안은 **D1-A: 실제 로컬 파일을 다루는 리더형 데스크톱 vertical slice**다.

1. 읽기/분할/모바일 상태, 파일 열기/미저장/오류/설정 화면의 클릭 시안 검토.
2. 후보 셸에서 한국어 IME·파일 읽기/저장·다시 열기·키 보관·TTS/카메라 capability spike. 결과로 플랫폼 결정 기록 작성.
3. 공통 DocumentSession/Store 경계 추출. 기존 npm/TUI 회귀 테스트 유지.
4. 파일 하나 읽기 기본 → 편집 버튼 → 소스 수정 → 저장 → 재실행 복구를 실제 GUI로 완성.
5. 테마/폰트/확대/목차, 한글·영어, QR 이미지 수신을 추가. 페이지 넘김·두 페이지·AI·TTS는 이 기반 위에 단계적으로 완성.
6. D1 종료 후 D2, 이후 D3. 데스크톱 검증 전에 계정/결제 서버를 먼저 구현하지 않음.

| 검증 축 | 필수 대표 시나리오 |
| --- | --- |
| 데이터 | 파일 전환 중 저장, 동시 저장, 외부 수정, 강제 종료, quota/디스크 부족, 복구 실패 |
| GUI | 읽기에서 숨은 편집 불가, 전환 위치 보존, 좁은 창/큰 폰트/두 페이지 fallback, 실제 버튼 hitbox |
| Unicode | 실기기 한글 IME, 일본어 조합, NFD, emoji·ZWJ, RTL 문서, 검색/Undo/붙여넣기 |
| QR | 실카메라+스크린샷, 역순·누락·중복·혼합, 낮은 대비, 크기 변경, 악성 gzip/파일명 |
| AI/TTS | 미지원 음성/모델, 오프라인, 취소, quota, 늦은 응답, 문서 전환, 원문 미변경, 전송 동의 |

| 후속 E2EE | reader 쓰기 거부, 키 바꿔치기, 철회, 기기 분실/복구, 중복·역순·재시작·로그 복원 |

통과 개수만으로 출시하지 않는다. 핵심 시나리오에는 실제 화면·파일 내용·복구 상태를 검증하는 assertion을 두고 OS/기기 미검증 목록을 공개한다. 성능 목표는 10KB/100KB/1MiB 문서와 표·코드 위주 문서에서 첫 표시·입력 지연·페이지 재계산을 측정한 뒤 확정한다.

## 13. 아직 사용자 결정이 필요한 항목

작업을 막는 질문으로 한꺼번에 요구하지 않고 해당 단계 착수 시 결정한다.

- 첫 목표의 웹 편집기 포함 범위와 추가 UI 언어 목록.
- 더블클릭 전환 기본값, 두 페이지/페이지 넘김의 첫 데스크톱 출시 필수 여부.
- 지원 데스크톱 OS/‘기타 앱’ 범위, 플랫폼 spike 결과에 따른 셸 선택.
- 최초 AI 공급자 수, TTS 백그라운드 재생과 추가 원격 음성 범위.
- 5MB 산정/이력 보존, 가입 인증 방식, C1 협업 출시 시점, 초대·유료 정책.
